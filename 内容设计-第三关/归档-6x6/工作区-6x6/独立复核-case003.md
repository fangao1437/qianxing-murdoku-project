### 5.3 为什么会有 3 条（幻影同伙成因，已用探针证实）

~~~~text
roles{thief=E, accomplice=nil} -> structure=true ｜ 线索不成立=1 ｜ inno(R1)=2 inno(R4)=1
roles{thief=E, accomplice=C  } -> structure=true ｜ 线索不成立=1 ｜ inno(R1)=2 inno(R4)=1
roles{thief=E, accomplice=D  } -> structure=true ｜ 线索不成立=1 ｜ inno(R1)=2 inno(R4)=0
C 在区域 #3（受害者相邻区 = {1,4}），D 在区域 #4
~~~~

- R4（k≥2 ⇒ 必有同伙 / 同伙同区）已于 2026-10-18 废止 ⇒ structure_report 不再对 accomplice 做任何位置约束；
- 线索里没有任何 @accomplice ⇒ 换 accomplice 不改变任何一条线索的真假；
- C 在 #3（**不在受害者相邻区**）⇒ 把 C 当同伙完全不改变 #1/#4 的无辜计数；
  D 在 #4，当同伙只会让 inno(#4) 从 1 降到 0，仍然 < inno(#1)=2 ⇒ R3 依旧成立。
- ⇒ 这三组角色都过结构、都只违反卡 5（allowed_false = 1）⇒ 求解器返回 3 条。

### 5.5 严格闸门 A 在这个设计下不可达（建议 Lead 修口径）

**一般性结论**：在「one_per_row + one_per_col + place_all + 没有任何 @accomplice 线索」的关卡里，
只要存在一个**不在受害者相邻区里**的无辜者 X，则 (thief = 真凶, accomplice = X) 必然也是一条合法解——
X 的位置不影响任何被比较区域的无辜计数，也没有线索提到 @accomplice。
本候选里 C 就在 #3（#3 与受害者区 #2 不相邻）⇒ **幻影同伙 C 无法通过结构或线索排除**。

可选的反制都不划算：
- 把 C 挪进 #1/#4 或改区域：会破坏「甜点师在茶点间」的叙事；
- 加 @accomplice 线索：本关已用掉 1 条假话额度，幻影解只会多违反 1 条 ⇒ 仍 ≤ allowed_false；
- 改引擎/求解器语义（把 level.roles 声明当作约束）：属于改运行时/工具，超出内容设计范围。

⇒ 建议 Lead 把「闸门 A」口径修正为 **A'：按 (摆位, thief) 去重后恰好 1 个解，且 = 声明的
solution + roles.thief**（不再要求「幻影 accomplice」也不存在）。理由：
1. 玩家侧只指认盗窃者，accomplice 不进入玩家输入（UI 提交通过后直接按 roles 结算）；
2. 现有 case_001（6 条解）、case_002（10 条解）同样过不了严格 A —— 若坚持严格 A，
   会把已定稿的前两关也判不合格。

按 A' 口径：本候选 **通过**（去重后 1 解 = 声明答案，thief = E）。

**需补的两处**：
1. **步骤 2 的列格不完整**：链子只写「北边茶壶、东边出房间，只剩西边 (3,3)」，
   没提南邻 (4,4)。(4,4) 属 R3（h,3,4 隔墙）⇒ 按「旁边=同房间」不算，结论仍对；
   但玩家读起来会疑惑，建议补一句「南边 (4,4) 属茶点间，隔墙不算旁边」。
2. **步骤 7 未显式排除「假话是其它五张之一」**：现在的写法是「先信卡1-4/6 推出摆位，
   再看卡5 与摆位冲突」——严格说这是「假设卡5 为假」后再验证，容易读成循环论证。
   建议补一步排除法（我独立枚举已证明它成立）：
   「若假话是卡1/2/3/4/6 之一，则其余五张（含卡5）必须全真 ⇒ 代入后无任何相容摆位（=0）。
    只有假话=卡5 时，其余五张给出唯一摆位 ⇒ 假话只能是卡5。」
   这一步正是闸门 C 的内容，建议直接写进玩家向推理链。

**全局依赖（需 Lead/产品确认，不是候选关卡的错）**：
- 步骤 7 的前提是「**全文至多一句假话**」。这是全作规则，但当前构建里 meta.announce **没有任何界面出口**
  （2026-10-18 副标题控件删除、关卡内 toast 也无处显示；见我的规格摘要 §1.5/§6.6）。
  如果玩家在此前关卡/教程中没有被告知这条规则，本关（以及 case_002）的「至多一句假话」前提
  无法从界面自证。**建议 Lead 确认规则告知渠道**（图例/教程/选关页说明等任一），否则推理链
  对玩家而言少一个前提。
- 卡 6 用 @thief 别名：引擎渲染为「盗窃者」、不泄露真名（我实测 clue 文案为
  「盗窃者 在 长桌 旁边」），玩家只需知道「盗窃者」是场上角色之一；这一点没问题。

## 九、额外发现与风险（按优先级）

### 9.1 P1：编辑器 row.3.1 .. row.3.6 四槽位内容尚未交付

候选只含 lua；卡片的**说话人/文案/头像/标记**由编辑器 row.N.k 四槽位决定。若不做，
卡片会走引擎回退文案（split_by_name 从正文里切第一个显示名）⇒ 卡 1 会显示成
「午后诗人」（线索主体）而不是说话人「司茶女仆」，与「说话人≠主体」的设计相反。
建议交付时在编辑器填（建议值见附录 A）。

### 9.2 P1：9 个新家具 kind 可能没有对应 obj.* 素材

候选新增的 kind：teapot / quill / jar / window / cake / knife / watch / rose / cushion
（既有已用过的 kind 只有 table / plant / carpet / chair / shelf / statue / case）。
如果调色板没有 obj.<kind>，真机上家具**不显示图标**——本关的推理大量依赖「看见器物位置」，
会直接影响可玩性。需 art-lead/素材补齐，或评估换成已有 kind（会牺牲叙事）。【读代码推断+规格摘要】

### 9.3 P2：位置提示会把答案送到玩家手边

卡 1-4 的位置提示各只亮 **1 格**，且正好是该角色的答案格；卡 6 亮 4 格（含答案格 (2,2)）；
卡 5（假话）也亮 1 格（软垫 (6,6)）。这是提示系统的正常行为（静态「允许位置」），
但玩家点一遍 6 张卡基本就能得到答案。属于难度/体验取舍，Lead 可决定：
接受（当作引导）、或本关关闭提示（若界面支持）、或调整家具布局让提示格变多。

### 9.4 P2：meta.announce 没有显示出口 + 「至多一句假话」的告知渠道

同 §七最后一条。announce=unknown 的设置本身没问题（case_002 同口径），
但需要产品确认玩家能从哪知道「至多一句假话」。这一条也是全作问题，不只本关。

### 9.5 P3：引擎文案是第三人称

引擎线索文案是「猫「墨」 站在 软垫 上」，而卡 5 在叙事里是猫的第一人称自辩
（「我整晚都趴在软垫上」）。编辑器 row 的 what 应填第一人称口供（建议见附录 A）；
引擎文案只作离线 dump/回退用。

### 9.6 P3：room_names 未写

候选没有 room_names 字段；若界面/选关缩略图要显示「长桌厅/月窗廊/茶点间/玫瑰廊」，
需要补 room_names（可选，不影响规则）。
