## A 原神《月谕圣牌》考据与美术资产

### A.1 系统背景

- 「月谕圣牌」是塔罗牌中的一整套大阿卡那，共 22 张；由「幻想真境剧诗·月谕模式」（10 幕 + 2 圣牌挑战）产出，每期只能抽取一次，可好友交换；成就名 Magnum Opus。
- 剧情：占卜魔女送的水晶球与「月谕之匣」；小狼说「要是能在隐秘的舞台上，为观众奉上如命运般无法预测的精彩表演，就可以找到装进这个盒子的珍贵藏品」。
- 月谕之匣官方描述：「借助『此刻』与『此地』的已知之物，推演未知的事理。」——与 Murdoku「摆位 + 推理」同构，可直接用作加载页文案。
- 官方条目：https://baike.mihoyo.com/ys/obc/content/506755/detail （SPA 抓不到正文）；全文以 biligame WIKI 镜像核对：https://wiki.biligame.com/ys/月谕圣牌 。

### A.2 《月谕圣牌·一·魔法师》原文（逐字）

> 意志如甘甜的茶水般流涌，
> 现实因兴致与闲暇而被塑造。
> 杯盏、羽毛笔、餐刀与装着甜点的圆盘，
> 小小的秘仪，调和的四质，
> 令人怀念的，午后的喧闹。
>
> 你说：万物皆备于我，
> 但归根结底，
> 那一个顷刻的欢笑与「魔法」，
> 也不过是无尽空无中
> 凝聚而成的一点光。

### A.4 整套 22 张牌的「套牌感」（8 条规律）

1. 同一套外框：银白尖拱 + 横幅 + V 坠饰 + 八角星徽；22 张的横幅/坠饰位置像素级一致。
2. 每卡一个主色家族：框恒定冷银，内景各自染色（魔法师=洋红/紫、女祭司=青绿/黑金、恋人=绯红/黑、月亮=青蓝/银、世界=金/青/米白、愚者=湛蓝/白/金）。
3. 白底浮空：不画矩形卡边，场景像徽章浮在纸面，元素可穿出框。
4. 画框即舞台：框内是小戏台，框外是另一个世界。
5. 框会破：愚者大面积碎裂、月亮/恋人裂缝、魔法师被玫瑰荆棘穿破——「框的完整性」是叙事变量。
6. 无脸/局部人体：整副牌回避正面清晰的脸（魔法师被裁头、女祭司只一只手、恋人背身/侧影）。
7. 每卡 2–3 件悬浮物：表达「魔法正在发生」。
8. 纹样库：尖拱、菱形四瓣花、八角星、卷草、荆棘玫瑰、四角闪光、纸面颗粒；文字只有横幅花体铭文一种。

> 「版画/蚀刻」说法的校准：框/纹样有石质刻线与颗粒做旧，但内景是柔和平涂数字渐变，不是粗黑木刻线；建议表述为「彩色石版画/绘本式哥特装饰插画 + 银灰石质尖拱框」。

### A.5 塔罗对照与转译

- 塔罗魔术师桌上四花色（权杖/圣杯/宝剑/星币）对应月谕魔法师桌上四件日用品（杯盏/羽毛笔/餐刀/甜点圆盘）；「万物皆备于我」对应「任他调用」；逆位=欺瞒/幻术。
- 月谕的「魔法」更小、更日常、更反讽：「一个午后的欢笑」而非「我即宇宙」；语气是第二人称 + 转折 + 叹息。
- 转译表（可直接复用）：茶水→意志流动；停摆怀表→被塑造的午后；四器→四客人/四质；「一点光」→失窃物/卡面存续；玫瑰荆棘→穿框/边界；无脸→被画框藏起来的真凶；「万物皆备于我」→凶手/猫的自辩；打翻茶杯与茶渍→事件痕迹。
- 版权边界：不复制/描摹原卡画作、不把官方卡图入库、不把人物立绘/logo/专有纹样当素材；只用官方内置素材 ID、自绘示意图与通用风格语汇（尖拱/银白石框/卷轴/八角星/深底/一主色/悬浮/无脸剪影）。卡面图仅本机观察，不入库。

## B 塔罗《魔术师》（Rider–Waite）速查

| 符号 | 含义 |
|---|---|
| 右手举杖指天、左手按地 | as above, so below（赫尔墨斯主义/翠玉录）；意志贯通上下 |
| 桌上四器（权杖/圣杯/宝剑/星币） | 四元素/四花色「全部备好，任他调用」 |
| 头顶无限符号 ∞ | 无限潜能；8 横置 = Ogdoad/无限 |
| 衔尾蛇腰带 | 循环/永恒 |
| 玫瑰与百合 | 欲望/纯洁；花园植物 |
| 水星/赫尔墨斯/炼金 Mercurius | 沟通、转化、骗术、机敏 |
| 红袍白袍 | 热情/纯洁的外在统一 |

- 正位：创造、意志、显化、沟通、技能、潜能、开始。
- 逆位：幻术、欺瞒、被揭穿的谎言、潜力未用、操控、空谈。
- 历史两层皮：Il Bagatto / Le Bateleur = 街头杂耍骗子；「杯球戏法（shell game）」三杯一球，与 Murdoku「摆位猜人」天然同构——魔术师从出身就是"让你看错"的人。
- 常见误传纠正：生命之树 Aleph/第 11 路径是愚者，魔术师是 Beth/第 12 路径（Kether→Binah）；月谕体系愚者排第 22、非 0；「as above, so below」出自《翠玉录》，不是塔罗原典。
- 可复用隐喻：魔术师=骗子/杂耍者；四器=四质；无限=停摆的午后/循环；指天指地=月窗（天上）与茶桌（地上）的呼应。

## C Murdoku 工程规格（实现仓实测）

> 以下来自对 qianxing-murdoku（HEAD 01a151f）与内容设计仓的逆向；所有结论区分「已实测 / 读代码推断 / 文档说法」。

### C.1 运行期到底强制什么

- rules：one_per_row / one_per_col / place_all；one_per_room 默认 false；tie_policy 只影响设计期结构检查。
- 受害者 V 也是棋子，需摆放；roles = { thief = "X" } 可以声明 accomplice（0 或 1）。
- submit() 只校验硬约束（每行每列、摆满）；运行期不校验线索、不比对 solution、不校验唯一解。提交通过后按关卡写死的 roles 结算。
- 同伙规则 R4（k≥2 必有同伙/同区）已废止；R3 只在设计期检查（受害者区域必须有相邻区；盗窃者必须在“相邻区域里无辜人数严格最多”的区）。
- meta.false_clue = 第 i 条线索是假（0 或 1 条）；announce 当前没有界面出口（none/one/unknown 玩家看不出差别）——假话必须能从矛盾中自证。

### C.2 硬性设计数字

- N×N 关卡：棋子数 = 行数 = 列数 = 卡线索数（place_all + 一人一行列 + clue_slots 测试）。
- 6×6 → 6 子 / 6 卡 / 编辑器 row.3.1–3.6；7×7 → 7 子 / 7 卡 / row.3.1–3.7（编辑器需扩一行）。
- 卡序 = 棋子序 = 线索序：卡 k ↔ clues[k] ↔ suspects[k] ↔ 编辑器 row.<关>.k。点第 k 张卡选第 k 枚棋子；高亮用 clue_hint(k)。
- 说话人由编辑器 row 的 who/face 决定，可与线索主体不同（case_001 已用）。
- 通用线索 general_clues 不占卡位，但需要编辑器 row.<关>.clue 容器，否则只出空白卡/不显示正文；不要轻易用。
- 线索卡上限 18 条（界面生成），一屏约 5 条（可滚动）；头像卡容量 ≤16。
- validate_level 只查格式/参数：不查 solution 行列合法性、不查 R3、不查唯一解、不查墙格式、不查棋子数与棋盘关系。

### C.3 线索原子（60 种）与退化清单

- 一行一列 + N 枚棋子下恒假（只能当假话）：left_of / right_of / above / below / between / beside（人对人）/ in_front_of / with_victim / distance 的 d=1。
- 恒真/无信息（别写）：not_beside（两人都摆上后恒真）、only_one_in_row（满盘恒真）、nobody_in_water（water 为空时恒真）。
- 好用且不要求同行同列：offset（dr/dc 精确位移）、row_offset / col_offset、distance（d≥2）、compass（ne/nw/se/sw）、abs_row_from / abs_col_from、corner / edge / inner、same_room / different_room、alone_in_room / alone_with / with_only、room_has、beside_object / on_object / only_beside / only_on_object、n_on_object / nobody_on_object、in_row / in_col / at、is_role / not_role。
- 角色别名：@thief / @accomplice / @victim；玩家看到的是「盗窃者/同伙/受害者」，不泄露真名。
- 复合线索（2026-10-17 新增）：nobody_on_object、below_in_other_room、alone_and_below_in_other_room——一句话塞两个事实，是 7 张卡压 7 人的关键。
- 位置提示：on_object 高亮家具自身可站格；beside_object 高亮家具四邻同房间可站格；in_row/in_col 整行/列；offset/房间/身份/复合类不做提示。

### C.4 设计期唯一解闸门（重要）

- tools/design_solve.lua 是设计期求解器（运行期已删）：枚举「摆位 × (thief, accomplice)」，要求结构 R3 + 线索违反数 ≤ allowed_false。它不看 level.roles，调用方要自己比对。
- 严格闸门 A（解数=1 且=声明答案，含角色）在“无同伙关卡”下不可达：求解器会枚举幻影同伙（同一摆位、同 thief、accomplice 不同）。case_001 = 6 条、case_002 = 10 条、7×7 v2b = 3 条（同摆位、thief=E、accomplice=nil/B/C，约 86s）。
- 推荐口径：A′ = 按 (摆位, thief) 去重唯一且 = 声明答案；D = 不同摆位 = 1 且 = solution；C = 假话剔除唯一（去掉第 i 条后相容摆位数：恰好一个 i 非空，其余为 0；全真 = 0）。
- validate_levels.lua 目前不查解数（2026-10-18 已删多解检查）；必须自己跑 design_solve。
- 已坏工具（需补 require("tools.design_rules") / 改调 design_solve）：dump_level.lua、new_level.lua、内容仓 design_gate.lua；find_clues.lua 等旧工具也需核对。
- 性能：6×6 全量约 1.3–6.5s；7×7 约 86s；8×8 不建议。

### C.5 家具 / 叠加层 / 测试影响

- objects[name] = { cells = {...}, occupiable = bool, kind = "..." }；occupiable=false 的格子不能站人；中文键必须用 ["名"] = {...}。
- 引擎把 kind 翻成 obj.<kind> 查调色板；旧关只用过 table/plant/carpet/chair/shelf/statue/case。新 kind 必须在编辑器 assets 配图，否则真机看不到家具。
- 桌面茶具/烛台建议走「叠加层图片子控件」，不写 objects、线索不引用；否则会改变可站性/解空间。
- 测试连带：tests/gray_unplace.lua 写死 6 行 + 夹具格 (1,1)(2,2)(3,1)(4,2)(5,3)；7×7 长桌固定占 (4,2) ⇒ 该测试 1 红，属测试假设需更新。clue_slots 要求 7 条；ui_math/level3_letter_map 多能自适应，但要复核。
- 工作区 lua/entry_client_script.lua:194 有 ASCII 双引号语法错误 ⇒ entry 与 dist 当前编译失败（HEAD 正常）；与关卡内容无关，交付前需修或回退。

## E 经验与方法（下次直接照做）

1. 先定 N、棋子、卡、行数四件套，再谈墙和美术；任何一项变动都要重跑 clue_slots/ui_math/gray_unplace。
2. 用洪泛确认房间数，不要用“墙的组数”推房间数；本案 3 组墙 = 3 间房。
3. 区分逻辑家具与美术叠加层：桌面茶具/烛台/桌布/红毯只做图；需要进线索的才写 objects。
4. 7 张卡压 7 人：4–5 条真位置 + 1 条假话 + 1 条身份/占卜 + 1 条复合，是可行配方；复合原子是救唯一解的关键。
5. 说话人 ≠ 主体：四张卡互相作证、只有猫替自己说话，既强化主题又降低线索量。
6. 验证纪律：validate_levels（格式/结构/假话）+ design_solve 全量（A′/D/C）+ 独立复核（自建判据）+ 推理链审读；不依赖运行时。
7. 假话不靠卡面视觉：七卡同构，不设计正逆位/褪色/描边；假话只能靠文案 × 座次 × 结构矛盾被发现。
8. 风格像但不抄：学卡框比例/配色/光/构图语法；不描摹原卡、不使用外部导入/官方图入库。
9. 落地前先查三样：编辑器 row 行数、家具 kind 调色板、测试夹具（尤其 gray_unplace 的 6 行/固定格）。
10. 重启时先做小验证：先复刻一张 6×6 的月谕风格关（不引新机制）验证美术管线，再上 7×7/复合线索。
