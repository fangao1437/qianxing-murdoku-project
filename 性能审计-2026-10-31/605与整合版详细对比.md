## 3. 运行逻辑的具体差别

### 3.1 判定位置比较

605每次检查都会遍历棋子，创建字符串片段表，再拼接位置签名。整合版在提交时创建扁平快照，按每棋子4个槽位记录id、是否放置、行、列，并显式保存棋子数量；后续检查逐项比较值。

收益是稳态检查不再创建位置字符串和中间表。代价是提交瞬间生成快照，比605多分配内存。棋子位置仍然逐次遍历，没有改为不可靠的“位置版本号”，未跳过变化检查。

### 3.2 判定动画完成后

605完成后仍继续遍历每个动画项并计算进度；整合版在位置、关卡、屏幕状态检查之后，若done与animation_complete都为真，直接返回。因此不会因为早退跳过正常位置变化检测。完成后时钟回退的行为与605有差异，见边界章节。

### 3.3 地板与地毯

地板：复用已有布局记录，原地更新x/y/w/h/show/face，不再每次新建布局表。

地毯：几何数值未变化时复用已有字符串签名；发生变化时仍回到原字符串比较路径，并保留实例缺失、显隐变化与原几何写入逻辑。没有移除约0.5秒纠偏逻辑。未简化家具显隐恢复，原有7次恢复调用仍保留。

### 3.4 圆环配置和清理

清圈后保留成功初始化的配置，下次绘制回读fillType、imageType、enableMask、reverseMaskArea、enableSoftEdge、fillRadialType。读取失败或不一致则重新初始化。amount/color/visible缓存失效，确保再次绘制不误跳写入。初始化失败的状态清除后允许重试。

判定圈增加活动对象集合，只清理绘制过或按名字复用的圈；隐藏、清色、径向复位任一步抛错时保留活动项供下次重试；全部成功才移除。保留原父控件解析和填充回读。长按圈也复用清理后的初始化配置。

### 3.5 明确保留的工作

父控件缓存、家具仅显隐恢复、引擎填充回读删减、光标检查删减和位置修订号替代均未实施。它们需要可靠的宿主生命周期证据，不能只凭离线桩证明安全。

## 6. 实机探针设计与测试方法

两版统一前缀为[QX605PROBE]。启动日志的version分别为605和integrated_b423aac；每5秒或600次回调汇总一次，切场景和销毁时补充汇总。

| 指标 | 意义 | 注意事项 |
|---|---|---|
| frames、dt_seconds、dt_max_ms、dt_gt33/50 | OnUpdate次数、宿主dt及长间隔数量 | dt单位按现有游戏脚本的秒口径；不是GPU测量 |
| OnUpdate_avg/max_ms | 整个原OnUpdate回调的CPU计时 | 使用os.clock；不可用则无计时项，不伪造数值 |
| verdict_present/done/animation_complete | 判定存在、完成及完成早退相关状态 | 605没有animation_complete，不要求该指标相同 |
| controller_start/clear_verdict、placement接口计数 | 提交、清理、比较频率 | 每帧的包装有额外开销 |
| verdict_invalidated | 判定经过step后被清除 | 需要结合操作场景解释，不等于错误次数 |
| ring_init_attempt、ring_after_clear、ring_paint_failed | 圆环初始化、复用和绘制失败 | 已有警告日志可辅助定位原因 |
| ensure相关handle_changed/missing | 同格返回句柄更换或缺失 | 不能直接证明对象底层是否重建 |
| clear_retry_objects、clear_nonzero_color | 清理失败残留与抽样清色回读 | 每十次清理抽样一次；读取不支持会单独计数 |
| adapter_sync_floor/spawn_whole_rug/furn_resync等 | 家具同步次数和耗时 | 不是每一个引擎原生API的完整计数 |
| heap_kb | 可用时collectgarbage('count')采样 | 不是累计分配，不主动触发GC，也不等于GC暂停时间 |

探针不修改判定结果或控件属性，但包装函数和抽样回读会产生额外CPU与分配。因此两版使用相同探针做相对对照，正式无探针版不根据探针绝对耗时直接宣称帧率收益。当前没有提供精确p50/p95/p99和GC暂停时长。

建议在同一设备、相同画质和窗口状态下，先605探针版再整合探针版，第二轮交换顺序；每场景至少30秒，各重复3次。人工试玩，不使用自动按键。

1. 主页静置30秒，进入同一关后静置30秒。
2. 摆出错误答案提交，等所有红绿圈完成后静置30秒。
3. 连续提交20次，再提交后立即改位置或撤销20次，记录是否残圈。
4. 长按放置/取消各20次，观察黄色进度圈是否正确渐进和清除。
5. 按现有UI切关、回主页、再进入共10轮，观察家具、地毯、头像和圆环。
6. 切换教程/可见界面后返回；若游戏支持重新进入造成控件重建，再做一次同样流程。
7. 返回两版完整日志，并标注每段测试起止时间、关卡和异常现象。不要只截单行汇总。

收到日志后，先比较场景窗口与调用频率，再定位失败/残留/失效；所有业务修正直接从无探针源码出发重新打包。诊断版仅重新派生，不把探针留进正式脚本。
