## 三 ★★★ 检查结果：**有多解，共 3 个**

```
结构合法 (摆位 × 角色) 组合 = 288
通过全部 5 条线索的解      = 3
其中【不同摆位】            = 1   ← 摆位其实是唯一的，就是关卡声明的答案
```

**三个解（摆位完全相同，只有"谁是盗窃者"不同）：**

| # | 摆位 | 盗窃者 | 同伙 |
|---|---|---|---|
| 解 1 | A(3,1) B(2,2) C(5,4) D(1,3) V(4,5) | **A 值班保安** | 无 |
| 解 2 | A(3,1) B(2,2) C(5,4) D(1,3) V(4,5) | **B 前台姑娘** | 无 |
| 解 3 | A(3,1) B(2,2) C(5,4) D(1,3) V(4,5) | **D 旧识古董商** | 无 |

⇒ **是"同一摆位 × 3 个盗窃者候选"这一种多解**，不是"摆位有多种"。

### 为什么无辜人数规则救不了它

受害者 V 在 (4,5)（区域 2），区域 2 里只有 V ⇒ k = 1 ⇒ 没有同伙。
相邻区域只有两个：**区域 1 = {A, B, D}（3 人）**、**区域 3 = {C}（1 人）**。

- 盗窃者 = A：无辜(区域 1) = 2，无辜(区域 3) = 1 ⇒ 最大在区域 1，A 在区域 1 ✔
- 盗窃者 = B：无辜(区域 1) = 2，无辜(区域 3) = 1 ⇒ 最大在区域 1，B 在区域 1 ✔
- 盗窃者 = D：无辜(区域 1) = 2，无辜(区域 3) = 1 ⇒ 最大在区域 1，D 在区域 1 ✔
- 盗窃者 = C：无辜(区域 1) = 3，无辜(区域 3) = 0 ⇒ 最大在区域 1，**C 不在区域 1** ✗

★★ **规则只能把盗窃者钉到"区域 1"这个房间，钉不到"人"** ——
而区域 1 里恰好站着 **3 个人**（A、B、D），所以规则对这三个人**完全一视同仁**。
无辜人数是从"哪个人是盗窃者"算出来的：把 A 换成 B 换成 D，
区域 1 的无辜人数**永远是 2**（3 人减去 1 个盗窃者）—— 等式两边一起动，**推不出新信息**。

### 这不是巧合，是结构性的

我穷举过本关**全部**摆位（每行每列各一人、避开家具格）：

```
不同摆位                       = 8640
其中能过结构闸门 R3/R4 的摆位   =  576
合法 (摆位 × 角色) 组合         = 1728
⇒ 能过结构的那 576 个摆位，每一个都恰好对应 3 种合法角色归属
```

⇒ ★★ **只要线索里没有任何一条提到"盗窃者"这个身份，
　 那么无论写多少条位置/家具线索，盗窃者都永远有 3 个候选。**
　 你这 5 条（地毯上唯一的人 / 桌子旁 / 椅子上 / 植物旁 / 最后一列）
　 **全部是在钉"摆位"** ⇒ 摆位被钉死了、身份没被钉住。

顺带更正一处前提：**每条线索单独看留下的可能格数**是

| 卡 | 线索 | 单独看留下的可能格 |
|---|---|---|
| 1 | 只有 A 站在地毯上 | 4 格 (2,4)(2,5)(3,1)(3,2) |
| 2 | B 在桌子旁 | 2 格 (2,2)(3,1) |
| 3 | C 站在椅子上 | 2 格 (4,2)(5,4) |
| 4 | D 在植物旁 | **6 格** (1,3)(2,2)(4,1)(4,3)(5,2)(5,4) |
| 5 | V 在第 5 列 | 5 格 (1,5)…(5,5) |

⇒ "只有 d 有两个可能的位置"与实测不符：**d 反而最松（6 格）**，
　 "两个可能格"其实是 b 和 c。不过这**不影响**结论 ——
　 无论每条多松多紧，缺了"身份"那条就注定 3 解。

## 四 ★★★ 采用「主动因素」规则后：**当前 5 条不用改，就是唯一解**

你 2026-10-17 定下的新规则（**设计够用即可，不追求普适定理**）：

> **盗窃者总是「选择」在无辜人数最多的相邻区域** —— 增加一层主动因素：
> 他是**有得选**的那个人。其余人被线索钉死在一格上，只有他最后还剩多于一个位置。

### 4.1 形式化定义（可直接实现、可复算）

```
S    = 与【全部线索 + 每行每列一人 + 家具占格】相容的摆位集合（先不看角色）
P(X) = 嫌疑人 X 在 S 里出现过的格子集合
判据 = 嫌疑人里【恰好一个】满足 |P(X)| > 1  ⇒ 那个人就是盗窃者
       ★ 受害者 V 豁免（它的位置本来就随别人变动）
然后把该盗窃者代回 S，过结构闸门 R3/R4 ⇒ 解应恰好 1 个
```

### 4.2 本关实测

```
S = 2 个摆位
  A ∈ {(3,1)}          1 格
  B ∈ {(2,2)}          1 格
  C ∈ {(5,4)}          1 格
  D ∈ {(1,3),(4,3)}    2 格   ← ★ 唯一模糊嫌疑人
  V ∈ {(1,5),(4,5)}    2 格   ← 受害者，豁免

⇒ 判定盗窃者 = D
⇒ 代回结构闸门后：解数 = 1，摆位 = A(3,1) B(2,2) C(5,4) D(1,3) V(4,5)  ✔ 与答案一致
```

★ 也就是说：**a、b 钉死 A/B → c 钉死 C → d 留下 D 的两个可能（(1,3) 与 (4,3)）→ v 随 d 变动**，
　 而 D=(4,3) 那个摆位过不了结构闸门（0 种合法角色归属）⇒ 只剩 D=(1,3)，
　 而 D 正是"唯一有得选的人" ⇒ 盗窃者 = D。
　 **这条链子与你原来的设想完全一致，5 条线索一个字都不用改。**

### 4.3 闸门

已写成可复用脚本 `tools/design_gate.lua`（配 `tools/design_clues.lua` 登记线索）：

```powershell
lua tools/design_gate.lua            # 跑登记的全部关卡
lua tools/design_gate.lua case_001   # 只跑一关
```

它同时报两件事：
- **闸门 A**（常规）：线索 + 结构规则 ⇒ 解数（本关 = 3，按 `rule = "ambiguity"` 只作信息项）
- **闸门 B**（主动因素）：唯一模糊嫌疑人 ⇒ 盗窃者 ⇒ 代回结构后的解数（本关 = 1 ✔）

★ 每关用哪条闸门在 `design_clues.lua` 里用 `rule = "ambiguity" | "standard"` 声明。
　 将来某关若这条规则也解不了，就按你说的改用相邻规则或补一条通用线索，
　 把那关改成 `rule = "standard"` 即可 —— **闸门不用重写。**

### 备选：卡 4 换成「盗窃者 不在 桌子 旁边」

| 卡位 | `type` | 参数 | 引擎文案 |
|---|---|---|---|
| 卡 4 | `not_beside_object` | `who = "@thief", object = 桌子` | **盗窃者 不在 桌子 旁边** |

**已用引擎自己的 `Core:solve` 跑过：1 个解 —— 盗窃者 = D，同伙 = nil，摆位 = 关卡答案** ✔

代价：丢掉「我在植物旁」；若想保留，可改卡 5（V），同样 7 种合格替换。
