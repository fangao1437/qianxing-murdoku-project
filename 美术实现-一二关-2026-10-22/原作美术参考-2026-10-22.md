## 2. 颜色解码规则（必须照做）

### 2.1 整数色：**0x00BBGGRR**

`GRID`/`OBJECT` 里的颜色字段绝大多数是字符串数字（例：`"10921645.000000"`），解码规则（实测自 puzzle-core `Rt()`）：

```
t = clamp(int(value), 0, 0xFFFFFF)
R = t & 0xFF
G = (t >> 8) & 0xFF
B = (t >> 16) & 0xFF
#RRGGBB = '#' + hex(R) + hex(G) + hex(B)
```

即 **低字节是 R**、高字节是 B（0x00BBGGRR）。例：`9419227` = 0x8FB3DB → `#dbb98f`（24h-delivery Porch 底色）。

### 2.2 字符串色：`#RRGGBB` / `#RRGGBBAA`

新版关卡（`puzzle_version>=2`，如 minigolf、house-party）直接用 `#RRGGBB` 字符串；带 8 位时最后两位是 alpha。`#` 开头时**不再**做 BGR 交换。

### 2.3 双色系统（家具）

每件家具最多两层颜色，来自两套可互换的字段名：

| 层 | 首选字段（按查找顺序） | 回退字段 | 作用 |
|---|---|---|---|
| base 层 | `obj_color_0_{id}` | `obj_color_base_{id}` | 乘在 `obj_<name>.svg` 上 |
| overlay 层 | `obj_color_1_{id}` | `obj_color_overlay_{id}` | 乘在 `obj_<name>_02.svg` 上 |

查找容器顺序（实测 puzzle-core `vn()` 内部 `N()`）：
- 首选：`CHARACTERS` → 根 → `GRID` → `OBJECT`
- 回退：`OBJECT` → `CHARACTERS` → 根 → `GRID`

> 注意：颜色既可能在 `GRID`，也可能在独立的 `OBJECT` 根（24h-delivery 就在 `OBJECT` 根里）、甚至 `CHARACTERS`（minigolf 的房间色/家具色都在 `CHARACTERS` 根里）。**四个根都要找。**

### 2.4 房间色（双通道）

| 通道 | 首选字段 | 回退字段 | 作用 |
|---|---|---|---|
| room_color_0 | `room_color_0_{id}` | `room_color_{id}` | **房间底色**（每格填充） |
| room_color_1 | `room_color_1_{id}` | `room_texture_color_{id}` | **地板纹理的乘色** |

- `puzzle_version<2`（旧格式）：先找 `room_color_0_{id}`/`room_color_1_{id}`，再找无 `_0_/_1_` 的回退字段。
- `puzzle_version>=2`（新格式）：**优先**找 `room_color_{id}` / `room_texture_color_{id}` 字符串色，再找带通道号的整数色。
- 房间完全没有色字段时，前端用固定 12 色板按 `room_id % 12` 取：`#ffcfca, #aed9f7, #b7e4ca, #f7eecd, #e1c9eb, #e7d6c7, #c1e4dd, #e6c5d0, #bee6e9, #dfc5c2, #c0d5e2, #b0ddc3`（实测 `Ge()`）。

### 2.5 家具染色语义（重要）

前端**不是**把家具整体替换成纯色，而是给图片套 `feColorMatrix` 做**逐通道缩放**：

```
R' = R * color.r / 255
G' = G * color.g / 255
B' = B * color.b / 255
alpha 不变
```

因为原始 SVG 是"白/灰模型 + 黑色描边"，结果就是：白色区域 = 目标色、灰色阴影 = 目标色的暗部、黑色描边保持黑色。**复刻时用"乘色"而不是"填色"。**

- 无 `obj_color_*` 字段时：不染色，家具呈现 SVG 原始白/灰配色（例如 24h-delivery 的椅背是奶白、桌面是灰白）。
- `table(4)` 与 `carpet(5)` **不绘制 overlay 层**（实测 `Bi()` 里 `p!==4&&p!==5` 才画 overlay；且这两件资产的 `_02.svg` 与本体内容相同）。
- 家具另带 CSS 投影：`drop-shadow(0 2px 0 rgba(0,0,0,0.35))`（基准 50px 格下偏移 2px，随缩放同比）。

### 2.6 主题（页面/墙/底格）

默认 **light 主题**（`darkMode` 默认 false）：

| 变量 | light（默认） | dark |
|---|---|---|
| `--cell-base` | `#fbfbfd` | `#0f0f0f` |
| `--cell-placed` | `#f0eef6` | `#151515` |
| `--wall-thin`（细网格线） | `#000000` | `#000000` |
| `--wall-thick`（粗墙） | `#000000` | `rgba(0,0,0,0.95)` |
| `--hover-preview` | `rgba(60,140,220,0.5)` | `rgba(80,170,255,0.6)` |
| 页面底色 | `#f2f0f7` | `#312f42` |

> 打印态：`--wall-thin: rgba(0,0,0,.3)`、`--wall-thick: rgba(0,0,0,.9)`（唯一在 CSS 文件里能直接读到的 `--wall-*` 定义，其余由 JS 主题表注入）。

## 3. 渲染口径（尺寸链 / 层级）

### 3.1 基准尺度

- 原作棋盘用 `display:inline-grid` 渲染，**基准格边长 k = 50 CSS px**（app-core `w2=50` 导出为 `k`），棋盘 padding = 2px（`l2=2`）。
- 整个棋盘再按 `effectiveGridScale`（0.35..2.5）做 CSS `transform: scale()`，**所有尺寸（墙厚/家具/标签/字号）同比缩放**。所以"占格比例"是唯一不变量，本文档统一用 **比例 = 尺寸 / 格边长** 表示。
- 关卡 JSON 里的 `cellsize`（150/225…）只是**作者坐标系**（`grid_rx/grid_ry/letter_xpos…` 的单位），与渲染尺寸无关。
- 参考图合成用 `--cell 120~180 px`，等价于把 50px 基准格放大 2.4~3.6 倍。

### 3.2 z-index 层级（实测 app-core 常量）

```
CELL_BASE 0 → CARPET 1 → HIGHLIGHT 3 → WALLS 4 → OBJECT 6 → NOTE 7 → BIG_LETTER 8 → HOVER 10 → HOLD_RING 50
```

房间名标签容器 z-index 9500（最上层）。渲染顺序：**格底色 → 地板纹理 → 地毯 → 不可占据格阴影 → 细网格线 → 粗墙 → 角饰 → 家具 → 门窗 → 标签**。

### 3.3 家具尺寸公式（实测）

```
G = 50px × 0.8 × (1 + objectSizePct/100) × meta.scale     // objectSizePct 默认 -5 → 系数 0.95
  = 50 × 0.76 × meta.scale
长边 = G，短边按 SVG 原生宽高比等比缩放         // 实测：canvas 渲染路径 Bi() 保持宽高比
居中放置（positionMode=center，可带 offsetX/offsetY）
```

- `meta` 来自 app-core 的覆盖表 `m2`（按 SVG 文件名匹配，见 `data/runtime-maps.json`），无覆盖则 `{scale:1, offsetX:0, offsetY:0, positionMode:'center'}`。
- **保持宽高比**是实证结论：我用 canvas 路径（保持比例）合成的 24h-delivery 与攻略站实机截图逐格一致；若按另一条 DOM 路径的"拉伸成正方形"假设则床/椅子明显变形、与截图不符。
- 多格家具：`6/119 Bed`、`21/22 Car`、`90 Carriage`、`56 Bus` 向右多占 1 格；`7/120 Bed_top` 向下多占 1 格；`54 Elephant` 占 2×2。被多占的格不重复绘制。
- 角饰（`corner_objects`）尺寸 = `50 × 0.8 × meta.scale`（**不乘** objectSizePct 系数），以格点为中心。
- 门窗图尺寸 = `格 × 0.72`，贴在格边中点（横边不旋转、竖边旋转 90°）。
- 地毯 tile 铺满整格（`格 × 格`）。

### 3.4 地板纹理合成（实测 canvas 代码）

```
1) 每格先铺 room_color_0 纯色
2) 纹理图层：texture_floor_*.svg（灰白模板）
     先 fill 房间 room_color_1 颜色 → globalCompositeOperation=multiply 叠纹理
     → destination-in 用纹理 alpha 裁形
   最后以 textureOpacity = 0.6（默认）整层叠加到格底色上
3) 房间 floor_type/room_texture 编号 = 9 或空 → 不铺纹理（纯色）
```

### 3.5 不可占据格阴影

`shadowBlocked` 默认开、`shadowOpacity` 默认 0.2：**不可占据格**（桌子/植物/书架/电视/雕塑等 `occupiable=false` 的家具格）整格再叠 `rgba(0,0,0,0.2)`，视觉上"凹下去"。空地与可占据家具（椅子/床/地毯/车等）不叠。

## 4. 墙 / 网格 / 外框规格（实测）

### 4.1 参数

| 参数 | 值（以基准 50px 格计） | 占格比例 | 出处 |
|---|---|---|---|
| 粗墙 `wallThickness` 默认值 | **5 px**（可调 2..10，选项 `mrd_wall_thickness`） | **10%** | index 默认选项表 |
| 细网格线 `gridlineThickness` | **1 px** | **2%** | GameScreen 墙渲染器默认参数 |
| 外边框 | 与粗墙同一条：棋盘最外圈四边都按粗墙 5px 画（在格内绘制，不额外扩边） | 10% | 墙渲染器 |
| 粗墙颜色 | light `#000000`；dark `rgba(0,0,0,0.95)` | — | app-core 主题表 |
| 细线颜色 | `#000000`（两主题同） | — | 同上 |
| 打印态 | thin `rgba(0,0,0,.3)` / thick `rgba(0,0,0,.9)` | — | index CSS 打印段 |

### 4.2 墙的判定规则（实测 + 算法复刻）

- 每格有 `room_code`；前端另算 `wallRoomIdByIndex`：`room_subroom_{id}==1` 的子区域会被**并入 `room_subroom_mainroom_{id}` 指定的主房间**，使子区域与主房间共享墙体轮廓。
- 对每一格的四条边：相邻格 `wallRoomId` 不同，或该边位于棋盘外边界 → 画**粗墙**；否则只画 2% 的**细网格线**。
- 结论：**粗墙 = 房间边界 + 外框**；细线 = 房间内部网格。同一像素位置先画细线再覆盖粗墙。
- 复刻建议：直接用"每格四边判断 + 两个厚度"实现，不需要画路径；注意格与格之间的粗墙是**两侧各画一半**（每格把边界画在自己格子内侧），拼起来正好 10% 格宽。

## 5. 房间名标签规格（实测）

| 属性 | 值 |
|---|---|
| 文本 | 房间名 **全大写**（`text.toUpperCase()`），允许换行由布局算法避让产生 |
| 字体 | 系统无衬线（页面 `--font-body: Inter, -apple-system, "Segoe UI", Roboto...`），`font-weight: 1000` |
| 字号 | `roomLabelFontPx` 基准 = **13 px @50px 格**；可选 `roomLabelScale` 0.7..1.6（默认 1）；非打印模式再乘 **0.9**（即默认约 **11.7/50 = 23.4% 格**）；打印模式不乘 0.9 |
| 字色 | `rgba(255,255,255,0.92)` |
| 描边 | `-webkit-text-stroke: 2px rgba(0,0,0,0.98)` + `paint-order: stroke fill`（基准 50px 格下的 2px；打印 2.75px） |
| 阴影 | 12 向 `text-shadow`（±1/±2 px 的黑描边扩散，`|dx|+|dy|<=3` 且非 0,0）× 0.98 黑 + `0 2px 4px rgba(0,0,0,0.55)` |
| 字距 | `letter-spacing: 0.35`（基准 px） |
| 位置 | 以计算出的标签点为**底部中心**：`transform: translate(-50%, -100%)`，然后 `top -= 3px` |
| 标签点计算 | `x = (room_name_xpos - grid_rx) / cellsize × 格像素`；`y = trunc((room_name_ypos - grid_ry)/cellsize) × 格像素 + 格像素`（即对齐到该行**底部**） |
| 避让 | 先夹进棋盘内（`x∈[w/2, 盘宽-w/2]`，`y∈[字号, 盘高]`），再迭代最多 10 轮：重叠时把可动标签移到另一个的右侧（+10px 间隙）或上方（-字号-4），已锁定的优先不动 |

> 参考图里 DINING ROOM / BEDROOM 等标签的落点与攻略站截图一致，说明上述换算式正确。

| 编号 | 纹理 | 观感 |

## 7. 地毯系统（实测）

- 数据：`carpet_objects_{a}_{b}`（值 = 5 表示该格是地毯）+ `carpet_objects_frame_{a}_{b}`（选边角变体）。
- 渲染：`carpet_objects` 的格子会渲染一张 `obj_carpet_tile{NN}.svg`（NN 1..49），**铺满整格**，颜色 = `obj_color_1_5` 乘色（注意：用的是 **id=5 的 overlay 色**，不是每格的色）。
- NN 的推导（实测 `Sn()`）：
  - 若该格有 `carpet_objects_frame` 值 `f` → `NN = f + 1`（用于拼长地毯/多格地毯）；
  - 否则按四邻是否也是地毯算位掩码 `mask`，`NN = mask + 1`（上 1 / 右 2 / 下 4 / 左 8），49 个 tile 正好覆盖 4×4 邻接组合与长条拼接。
- 坐标对顺序：旧格式 `puzzle_version<2` 用"排序后唯一坐标压缩映射"（对 0 基/1 基、XY/YX 自动择优）；新格式直接 `(row,col)`。
- 渲染示意与 24h-delivery 实例见 `render/家具-重点6种.png` 底部 4 张 + `render/level-puzzle-24h-delivery-easy.png`（Porch 地毯、Bedroom 竖条地毯、Kitchen 地毯）。

## 8. 家具规格（核心）

### 8.1 资产结构（实测）

- 每件家具最多两个 SVG：
  - `obj_<name>.svg`：**base 层**（白色/灰色模型，白=将被染色，灰=暗部，黑=描边）；
  - `obj_<name>_02.svg`：**overlay 层**（第二色覆盖件，如椅垫花纹、被子、植物叶子、书脊）。
- 少数资产本身带固有颜色（例：`obj_statue.svg` 是蓝灰色石雕、`obj_piano.svg` 是深色钢琴），这类会被同样乘色，颜色会被"染上一层"。
- 渲染顺序：base（乘 `obj_color_0`）→ overlay（乘 `obj_color_1`，`table/carpet` 除外）→ 都有 `drop-shadow(0 2px 0 rgba(0,0,0,.35))`。
- 占格比例口径：`长边 = 格 × 0.76 × m2.scale`；短边按 SVG 宽高比。

### 8.2 项目两关必需 6 类（形状要点 + 双色 + 占格）

## 11. 给「千星可用素材」的映射建议（初稿）

目标：用「官方基础形状 100001–100006 + 内置素材 + 文本」拼出与原作同构的俯视图。全部按"从正上方看"的扁平几何做，**不需要透视/纹理细节**，靠颜色和剪影区分。

| 原作对象 | 几何分解（正上方看是几块什么形状） | base 色 / overlay 色（24h-delivery 实测） | 占格 |
|---|---|---|---|
| **chair 椅子（扶手椅）** | 圆角方块主体 1 块 + 上沿一条圆角靠背 1 块 + 左右两条竖向扶手 2 块 + 坐垫内框 1 条（overlay 色描线） | `#fef7e4` / `#fbd592` | 长边 ≈0.84 格 |
| **table 桌子** | 大圆角矩形桌面 1 块 + 下方深色桌沿条 1 条 + 两条桌腿小矩形；长桌＝2~4 个同色矩形无缝横/竖接 | `#e0ce7b` / `#ad9c67`（overlay 不画） | 0.84 格/段 |
| **carpet 地毯** | 整格矩形 1 块 + 内嵌细边框 1~2 层（角上有小缺口）；多格地毯用九宫格边/角拼 | base `#fdeea5` / overlay `#fee08e`（游戏只用 overlay 色染 tile） | 1.0 格/格 |
| **plant 盆栽** | 开口花盆 1 块（梯形/圆角矩形）+ 6~9 片从盆心向外放射的尖叶（旋转的细长圆角矩形/椭圆） | 盆 `#fca161` / 叶 `#79cfa1` | 0.76 格 |
| **shelf 书架** | 竖向矩形柜体 1 块 + 2~3 条横向隔板线 + 十几条竖书脊小矩形（overlay 色） | `#d0b0d9` / `#b2dbeb` | 0.82 格 |
| **statue 雕塑** | 方形台座 1 块 + 台座上一尊人形剪影（头=圆、躯干=圆角矩形、披风=三角形）；不可站人 | `#ffffff` / `#c0c0c0`（保留石膏灰蓝） | 0.91 格 |
| （参考）bed 双人床 | 左侧枕头白色圆角矩形 + 右侧被子第二色大矩形 + 床架描边；横向跨 2 格 | `#fffbe7` / `#ffd98e` | 1.67×0.84 格 |

**通用做法**：
- 每个对象画在一个"逻辑格"坐标系里，长边取 **0.76~0.91 × 格宽**（同一关里保持统一基准，仅靠 `m2.scale` 微调：椅子/桌子 1.1、书架 1.08、植物 1.0、雕塑 1.2 → 实际 0.76~0.91 格）；短边按各自宽高比（0.62~1.05）自然缩短。
- 每件固定两层色：主体用 `base` 色、覆盖件/内部线用 `overlay` 色；**不要**给纯色方块描黑边（原作黑边是 SVG 描边 + 白模乘色后的自然结果，可用 1px 深色描边近似）。
- 不可站人的家具格在格子上再压 `rgba(0,0,0,0.2)` 的整格暗层（原作 `shadowBlocked`），这是"凹下去"观感的关键。
- 长桌/长地毯用**同色矩形拼接**并去掉接缝描边，即可得到原作那种"一件大桌/大地毯"的效果。

## 12. 实测 vs 推断（诚实标注）

**实测（有代码/数据出处）**
- 颜色编码 0x00BBGGRR、#hex 直用、双色字段与回退链、查找容器顺序；
- 每关房间表/家具矩阵/地毯矩阵/门窗/角饰/标签坐标（由线上 JSON 按 puzzle-core 解析器规则复刻）；
- OBJECT 表 0..151（149 项）的 id/名称/occupiable/svg 文件名；
- 对象几何覆盖表 `m2`（scale/offset/positionMode）与公式"长边 = 格 × 0.8 × 0.95 × scale"；
- 双层乘色（feColorMatrix 逐通道缩放）与投影 `0 2px 0 rgba(0,0,0,.35)`；
- 墙厚 5/50=10%、细线 1/50=2%、判定规则（wallRoomId 不同或出界）、外框与粗墙同宽；
- 标签字号 13×(scale)×0.9 / 描边 2px / 颜色 / 大写 / 位置换算与避让算法；
- 默认选项（objectSizePct -5、textureOpacity .6、shadowOpacity .2、wallThickness 5、roomLabelScale 1）；
- 地板纹理编号→文件映射（24 种）、纹理=灰白模板×room_color_1×60%；
- 地毯 tile 编号规则与 tint=obj_color_1_5；
- 渲染交叉验证：`puzzle-24h-delivery-easy` 合成图与非官方攻略站实机截图逐格一致（房间布局/地板/墙/标签/家具形状）。

**推断/近似（需注意）**
- 家具占格比例按"保持宽高比"口径计算（线与攻略站截图一致；理论上 DOM 代码还有一条"拉伸成正方形"的旧路径，仅用于开场动画，未采用）；
- 参考图标签字体用 Segoe UI Black 近似原作的 Inter/system-ui 1000 字重，字宽有 1-3% 误差；
- 门窗 `room_windows_*` 的数值只当开关，未区分窗样式（目标关无窗数据，不影响）；
- 未渲染 void 格（原作 `Void` 是透明挖空）；目标关无 void。
- 6 个线上 404 的关卡未取证（与本任务无关）。

## 14. 一句话结论（给设计文档直接抄）

- **家具 icon 尺寸统一按"格比例"缩放**：长边 = 格 × **0.76 ~ 0.91**（椅子/桌子 0.836、书架 0.821、植物 0.760、花丛 0.760、雕塑 0.912），短边按 SVG 原生宽高比缩短；长桌/床这类多格件按多格宽再乘 scale（床横跨 2 格、长边 1.67 格）。
- **carpet 双色**：`obj_color_0_5`（base，24h `#fdeea5`）/ `obj_color_1_5`（overlay，24h `#fee08e`）；但游戏里地毯只用 **overlay 色**给 `obj_carpet_tileNN.svg` 乘色，base 色基本不参与。
