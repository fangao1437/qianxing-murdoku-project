## 2 千星官方素材检索结论（1543 张全量）

检索范围（可复查）：`https://qx.070077.xyz/api/library/catalog` 全量 **1543 张 / 14 类**，
逐类接触表 21 张（`_work/art-slot/sheets/`，带 id + 行列号）；106xxx 全 96 张逐张测量尺寸/透明边/覆盖率/可染性。
（接触表与测量数据留工作区，不随仓分发——含素材截图。）

### 2.1 家具槽位：**0 张严格俯视家具**

唯一"真家具"是**等距 3/4 视角**的 `105091–105096`（桌/椅/书桌/床/圆桌/摊位，自带颜色、乘算只能压暗）；
**植物是唯一能单张直出的槽位**（`105313` 盆栽 / `105315` 深盆白花 / `105135` 灌木 / `105136` 草丛 / `105137` 草丘 / `105083` 正俯视黄花）。
⇒ 家具只能"官方白模 × 多层拼装"。

### 2.2 能用来拼的零件（**多层方案实际用到的**）

| 用途 | 素材 id | 关键实测 |
|---|---|---|
| 台面 / 柜体 / 线 / 书脊（直角、可任意拉伸） | **100001** 基础形状·矩形 | 纯白 256²，**直角完美、无缺口、拉多细都不脏** |
| 叶簇 / 肩头 / 圆头 | **100002** 基础形状·圆形 | 纯白 256² |
| 粗描边圈（本轮未用） | **100006** 圆环 | 线宽 ≈6.9% |
| **柔和投影** | **106056** 柔光圆 96² | 白心不透明 → 向外渐隐；染深=柔和圆影（首选，可见圆 ≈91px 正好一格） |
| （第一轮用过、**本轮弃用**）圆角方板 | 106053 / 107102 / 107002 | 106xxx 四角半径不一致/带缺口；107xxx 干净但部分带装饰角 —— 见 §2.4 |

### 2.3 地板纹理：**没有木纹、也没有可平铺瓷砖**

最优三个是 104005（纯白斜纹暗纹）/106054（纯白方格）/107106（灰噪点，会压暗发脏）。
⇒ 本轮地板仍是**纯色 + 房间色**；木地板只能自绘或接受纯色（下一轮）。

### 2.4 ★ 大坑：官方"圆角矩形"基本都有手绘缺口（[实测]）

- 106053 四角 r≈2.4px 但四边有 9% 毛边；106046 四角半径 `[15.7, 6, 2.4, 0]` + 底边 1.7% 缺口（"纸片感"来源）；
  106045 四角近直角（右上/左下被切平）、106037/106040/106048 缺口 9%–99%。
- 107xxx 系列干净（107009/107265/107253/107102/107002），但 107002 自带**装饰角**（像画框）。
- ⇒ **结论：主体/台面/柜体一律用 `100001` 直角矩形**，靠"深色外形垫底"提供描边与层次；
  这样在 89–108px 的格子里**最干净**（第一轮用 106053/107002 时出现的"纸张/相框感"就是这些缺口造成的）。

## 3 本轮方案：家具六层元素分解（定稿 v300）

> 数据文件：`家具元素分解-v300.json`（本目录；由 `lua/furn_art.lua` 经 `_work/art-work/dump_spec.lua` 导出，等于工程实际数据）。
> 坐标单位 = **格子**；`dx` 右为正、`dy` **下**为正；颜色 `0xAARRGGBB` 与素材**乘算**；游戏内 `anchoredPosition.y = -(dy × 格高)`。

### 3.1 定稿数据在 `家具元素分解-v301.json`

那份 JSON 是 `lua/furn_art.lua` 的**直出**（`_work/art-work/dump_spec.lua` 生成），逐层给了
`{ layer, id, asset, w, h, dx, dy, color }`，单位 = 格子、`dx` 右 / `dy` 下为正、颜色 `0xAARRGGBB`（乘算）。
表中 `variants` 的键：`"1"` = 单格、`"h2"` = **横放两格长桌**、`"v2"` = **竖放两格长桌**。

**各件部件构成（照原作，从下往上）**

| kind | 部件（层序） |
|---|---|
| 椅子 | 投影 → 棕金轮廓 → 主体 → 靠背内区 → 靠背顶带 → 坐垫 → 前缘 → 左扶手 → 右扶手 |
| 桌子（单格 / h2 / v2） | 投影 → 黑描边 → 桌面 → 桌沿 → 左腿头 → 右腿头（横放：桌沿在长边下方、腿头在两端；竖放：桌沿与两只腿头都在底边） |
| 书架 | 底部投影 → 粗黑外框 → 柜体 → 顶板 → 内凹黑框 → 隔板 1 → 隔板 2 → 书脊 1..5 |
| 植物 | 投影 → 叶 L 黑边 → 叶 L → 叶 R 黑边 → 叶 R → 叶 M1 黑边 → 叶 M1 → 叶 M2 黑边 → 叶 M2（亮）→ 盆沿 → 盆身 → 盆底暗 |
| 雕塑 | 投影 → 台座底黑边 → 台座底 → 台座上层 → 台柱 → 肩 → 头 → 头高光 |
| 地毯 | 外框 → 内面 → 内框线（三层都按"整块矩形 ∩ 本格"切） |

**关于"描边"**：原作的黑描边是**素材里的黑色填充块**（桌 ≈2.5% 格、书架 **5%**、植物 1~1.5%），
我们只能"用一块略大的深色矩形垫在下面"来近似 ⇒ 有描边、但拐角与宽度不如原作精细。
**椅子例外**：原作椅子**没有黑描边**，轮廓来自 overlay 线画层（棕金色）⇒ 我们用"略大的棕金矩形垫底"。

**试过但否掉的**（留证据，免得后人重试）：`106032` 当椅框（框内还有圆环花纹 ⇒ 像相框）；`106046` 当桌面（卡片/纸张形状）；
`106038` 当靠背（**空心**描边胶囊 ⇒ 染色后是深色胶囊）；`107002` 当台面（**自带装饰角** ⇒ 像画框）；`105090` 奶白瓮当雕塑（一格下太花）。

### 3.2 跨格家具：分组 + 锚点格 + 溢出（用户要求"不许拆成两格"）

```
① 分组：按 object 键做 4 邻接连通分组；**只有 table / carpet 参与合并**
        （其它家具一格一件——两盆相邻的植物是两盆，不是一件两格家具）
② 锚点：整件美术只画在"组的右下格"（行最大、行相同列最大）
③ 坐标：元素以**整件包围盒中心**为原点，换算到"锚点格中心"为原点 ⇒
        允许 w/h > 1 格、dx/dy 超过 ±0.5（横放长桌 w = 1.92 格、竖放 h = 1.92 格）
④ 层序：锚点格由脚本 `SetAsLastSibling()` 抬到 stage 子列表最后
        （否则邻格的 face 是不透明房间色，会把溢出的一半盖掉）
⑤ **横竖两套美术**：`table["h2"]` / `table["v2"]` 各自摆桌沿与腿头 —— 用户明确要求"横桌竖桌明显需要分开做"
```

### 3.2 ★ 跨格家具：分组 + 锚点格 + 溢出（用户明确要求"不许拆成两格"）

```
① 分组：按 object 键做 4 邻接连通分组；**只有 table / carpet 参与合并**
        （其它家具一格一件——两盆相邻的植物是两盆，不是一件两格家具）
② 锚点：整件美术只画在"组的右下格"（行最大、行相同列最大）
③ 坐标：元素以**整件包围盒中心**为原点授权，换算到"锚点格中心"为原点 ⇒
        允许 w/h > 1 格、dx/dy 超过 ±0.5（例如竖放长桌：h = 1.90 格）
④ 层序：锚点格由脚本 `SetAsLastSibling()` 抬到 stage 子列表最后
        （否则邻格的 face 是不透明房间色，会把溢出的一半盖掉）
⑤ 竖向/横向：美术只按"长轴 = X"画一次；实际是竖的（包围盒高 > 宽）时，运行时交换 dx/dy 与 w/h
```

**为什么不让地毯也溢出**：地毯可站人，溢出会盖住邻格的人像/笔记；地毯改用 §3.3 的"逐格切矩形"。

### 3.3 地毯：按整块包围盒逐格切矩形（视觉连续、可站人）

三层都是"整块矩形与该格的交集"：

| 层 | 内容 | 说明 |
|---|---|---|
| ① 外框 | 整格铺满 `#B89A62` | 相邻格同色 ⇒ 拼起来无缝；**格线会在它上面透出**（原作也把网格线画在地毯之上） |
| ② 内面 | 包围盒内缩 `RUG_INSET=0.12` 后与本格求交 `#DCC684` | 只有**整块的外缘**才有"框"，组内相邻格之间没有 |
| ③ 内框线 | 再缩 `RUG_LINE=0.20` 求交 `#C9B072` | 双层边的层次 |

⇒ 2×1 的地毯在屏幕上是一整块带双线边框的地毯（JSON 里有 `sliceRule.example2x1` 两格的实测数据）。

## 9 第四轮（v302）：改用**外部拼图工具的结果**当"拼法"（2026-10-22）

用户判词：「**桌子椅子植物依然没有达到参考效果，仓库里有一个能兼容千星的外部图片网站，

### 9.1 用的是哪个站、怎么用的

| 项 | 内容 |
|---|---|
| 站点/仓库 | `https://qx-img.070077.xyz`（千星奇域拼图工具）→ 源码 `github.com/1475505/Miliastra-toolbox-primitive-shape`（已 clone 到工作区 `_work/art-tools/`） |
| 用法 | 用它的**本地引擎**（`server.py --cli`）把原作图标拟合为图元：PNG 模式（保留透明底）、只允许**椭圆**、N = 160~200 |
| 结果文件 | 工具导出的 `.lua`：`PALETTE`（RGB 表）+ `ELEMENTS` 记录 `{kind, cx, cy, w, h, rotZ, colorIndex, alpha}` |

|---|---|---|

| 桌子/地毯 | 手搭 6 层（黑描边/桌面/桌沿/两腿头） | **保持不变**：桌子是直角长边，椭圆拟合会糊；地毯是平面矩形 |

### 9.3 已知取舍（写清楚，免得下一轮重踩）

1. **椭圆拟合 ≠ 矢量还原**：工具用半透明椭圆逼近，形体圆润的家具（椅子/植物/书架/雕塑）效果明显好；
   直角/直线件（桌子）会发糊 ⇒ 桌子保留手搭。
2. **工具用来铺底/光晕的大椭圆要丢掉**（`gen_art_records.py` 里按"比整件还大 / 低透明度大块"过滤），
   否则搬到格子里是一圈脏光晕。
3. **控件量**：一件家具 151~200 个图片控件，运行时实例化；工程侧设了"每格 260 个"上限（`cfg.furn_prim_cap`）。
4. 工具结果里的旋转是**客观数据**，游戏里用 `SetLocalRotation(0,0,rotDeg)` 原样使用（工具自己的 Lua 运行时也这么写）。

### 9.4 下一步可试的路

- 换用 `github.com/1475505/Miliastra-image-editor-webui`（同作者的**场景编辑器**，支持 SVG/CSS 导入 → 导出 GIA）：
  它有可能把**原作的 SVG 矢量**直接拆成"矩形/椭圆/星形/圆环"图元，比"图像拟合"更像矢量复刻（本轮未走完：GitHub 克隆被网络重置）。
- 或者把工具的拟合条数按件分配（植物/书架 200、椅子/雕塑 120），在效果与控件量之间取平衡。
