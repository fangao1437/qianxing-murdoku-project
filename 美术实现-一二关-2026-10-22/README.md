## 0 一句话结论

**官方素材库里「严格俯视的家具」是 0 张**（1543 张全量检索，见 §2），所以第一二关的家具**不可能"一张图直出"**。
本次按原作机制（**双层白色剪影 + 双色染色**）改成「**每格 3 层官方基础形状拼装**」：

| 层 | 语义 | 素材 | 作用 |
|---|---|---|---|
| L1 `obj` | 深色外形 | `100001` 纯白方块 / `106053` 纯白圆角方板 / `100002` 纯白圆（按件的形状选） | 当作**描边/木框**（原作那圈粗描边的等价物） |
| L2 `obj2` | 主体 | 同上 | 桌面/坐垫/地毯面/陶盆等 |
| L3 `obj3` | 细节 | 同上（雕塑用 `105090` 奶白瓮） | 靠背条、书架层板、叶簇高光等 |

⇒ 结果：**同一套 6 种家具（table/chair/carpet/plant/shelf/statue）全部有可辨识的形状**，不再是纯色方块；
   每格控件数 +2（14→16），两张关卡最多 36 格 ⇒ +72 个客户端控件（官方上限 1000/组，留有余量）。

## 1 原作美术基准（要复刻的东西长什么样）

### 1.1 机制（[原作] 从关卡 JSON + 资产文件读出）

| 项 | 原作法 | 出处 |
|---|---|---|
| 家具 | **两层白色剪影**：`obj_<名>.svg`（base）＋ `obj_<名>_02.svg`（overlay），全部 path 是 `fill='#fff'` 纯白 | `/play/assets/obj_*.svg`（416 个资产） |
| 家具配色 | 关卡 JSON 里的 **`obj_color_base_<objId>` / `obj_color_overlay_<objId>`**（`#RRGGBB`），按两层分别乘算 | `play_puzzles/en/*.json` |
| 房间地面 | `room_color_0_<room>`（底色）＋ `room_texture_<room>`（纹理编号）＋ `room_texture_color_<room>` | 同上 |
| 墙 | **房间边界与外框是粗黑线**，房间内部是细网格线（CSS 变量 `--wall-thick` / `--wall-thin`） | `/play/assets/index-*.css` |
| 房间名 | 每间一个文字标签（`room_name_<id>` + `room_name_xpos/ypos`），白字深描边 | 同上 |
| 家具比例 | **保持宽高比**（不是拉伸成正方形）；床 2:1 长条、椅子是竖长扶手椅 | [实测] 与 fansite 实机棋盘截图逐格比对 |

### 2.3 地板纹理：**没有木纹、也没有可平铺瓷砖**

| 候选 | 结论 |
|---|---|
| 104005 纯白斜纹 164×164 | 最"不脏"的暗纹，可当叠加层（但没有多余图层可用） |
| 106054 纯白方格 68×68 | 可当瓷砖格线（下一轮可考虑当 `face` 底图） |
| 107106 灰噪点 152×152 | 全库唯一颗粒纹理，乘算后压暗 41%，浅色房间会脏 |
| 结论 | **本轮地板仍是"纯色 + 房间色"**；木地板只能自绘或接受纯色（下一轮） |

### 2.4 硬约束（会影响后面所有美术）

1. **九宫格拿不到**：catalog 的 `border/*.json` 全部 404 ⇒ 只能整图 Stretch，圆角框会被拉变形（因此各层尺寸要挑接近素材原始宽高比的）。
2. **imageColor 是乘算**：只能压暗；要亮色只能用纯白模。
3. **模拟器不渲染非基础形状**：106xxx/105090 在模拟器里会显示缺失框，观感必须走离线预览（§5）与真机。
4. **外部 .gia 进不了客户端控件容器**（项目既有结论）：所以"把图导入当 UI 图"这条路不通，只能是"官方素材 + 控件拼装"。

## 3 本轮方案：家具三层元素分解（定稿 v11）

> 数据文件：`家具元素分解-v11.json`（本目录）。坐标单位 = **格子边长比例**；`dx` 右为正、`dy` **下**为正；
> 颜色 `0xAARRGGBB` 与素材**乘算**；游戏内 `anchoredPosition.y = -(dy × 格高)`。
> 颜色取自原作双色就近换算（椅 base `#fefeec` / overlay `#c2c18e`；桌 base `#d4cca0`；雕塑灰系）。

| kind | L1 外形（描边） | L2 主体 | L3 细节 |
|---|---|---|---|
| **table** 桌子 | `100001` 0.90×0.64 `#4A3524` | `100001` 0.82×0.56 `#D4CCA0` | `100001` 0.72×0.46 `#E8E2C0` |
| **chair** 椅子 | `106053` 0.74×0.76 dy+0.04 `#4A3A2A` | `106053` 0.66×0.50 dy+0.13 `#F2EBD4` | `100001` 0.62×0.20 dy−0.16 `#CBBE97`（靠背） |
| **carpet** 地毯 | `100001` 0.92×0.92 `#9C8A63` | `100001` 0.84×0.84 `#DCCBAA` | — |
| **plant** 植物 | `100002` 0.64×0.52 dy−0.08 `#3E7D3A`（叶簇） | `106053` 0.32×0.24 dy+0.26 `#8A6A48`（陶盆） | `100002` 0.34×0.26 dy−0.20 `#58A046`（叶簇高光） |
| **shelf** 书架 | `100001` 0.82×0.66 `#4A3524` | `100001` 0.76×0.60 `#B4874F` | `100001` 0.68×0.07 dy−0.05 `#4A2E17`（层板） |
| **statue** 雕塑 | `100001` 0.54×0.24 dy+0.28 `#4E4E56`（基座） | `105090` 0.60×0.50 dy+0.02 `#C9C9D2`（奶白瓮→灰） | `100002` 0.14×0.10 dy−0.22 `#E2E2E8`（顶饰） |

**为什么是"深色 L1 当描边"**：原作的辨识度有一半来自那圈粗黑描边；官方白模没有描边，
于是用"同形状、放大 10%、染深色"垫在下面 ⇒ 视觉上等价于描边（4–5px @108 格）。

**试过但否掉的方案**（留证据，免得后人重试）：

| 方案 | 否掉原因 |
|---|---|
| 椅子用 `106032`（84×84 粗圆角框）当框 | 框内还有圆环+四角圆点花纹，放大后像**相框** |
| 靠背/桌面用 `106046`（172×116 实心圆角矩） | 形状是"卡片/纸张"（底边有缺口、角有撕裂）⇒ 像一张纸 |
| 靠背用 `106038`（176×60 胶囊） | 它是**空心**描边胶囊，染色后是一根深色胶囊，不像靠背 |
| 植物用官方彩色盆栽 `105313` | 花盆上有两个白底红边的"眼"，像怪物；且与扁平基础形状风格不统一 |
| 靠背/桌面用 `106045`（128×76 圆角矩） | 右上角有撕角，放大可见 |

把原来的「淡紫」换成「暖灰」，让 3–4 个房间并排时像**一间屋子的几块地面**（原作截图就是这种暖调平面图）：

## 6 与原作的差距（如实记）

| 项 | 现状 | 差距/后续 |
|---|---|---|
| 家具描边 | 用深色 L1 近似 | 原作是真·黑色 stroke；我们没法画 stroke，只能"垫一圈深色" |
| 家具造型 | 几何拼装（桌/柜/椅/植物/雕塑可辨识） | 原作是插画级剪影（扶手椅有扶手弧线、床有枕头褶皱）；3 层已到上限，再细要加层或改拟合 |
| 地板 | 纯色（房间色） | 原作有木纹/瓷砖/草地纹理；本轮无可用平铺素材 |
| 房间名 | 无（只有"区域N"） | 原作每间有名字标签（BEDROOM/KITCHEN…）⇒ 建议下一轮加（文本控件静态摆放即可） |
| 墙/门 | 已是"粗墙 + 橙色门段" | 原作墙是纯黑；门的表达不同（原作是门框/窗） |
| 家具比例 | 各层按 0.9–0.7 的格子比例摆放 | 原作"保持宽高比"，我们按格子比例（Stretch）⇒ 非正方形素材会轻微变形（本轮已规避：关键形状都用正方形素材） |

## 7 下一轮建议（按性价比排序）

1. **房间名标签**（文本控件，纯静态）—— 原作辨识度提升最明显、成本最低。
2. **地板纹理**：`face` 的底图从 `100001` 换成 `106054`（方格砖）或 `104005`（斜纹暗纹），按房间色乘算；
   只需改 `cfg.cells.face_image` 一处，但要先确认真机上 106xxx 在 `face` 上能渲染。
3. **家具第 4 层**（或把 L1 换成"描边专用"素材）：给扶手椅加两个扶手、给床加枕头。
4. **真机验收**：`InstantiateClientUIControl` 是否把模板新增的 `obj2/obj3` 一起克隆 —— **这是本轮唯一没在真机验证的假设**
   （同类先例：v283 的 `portrait` 层是同一个 content 下克隆出来的，真机已通过）。
5. 若真机通过，再考虑把 `obj2/obj3` 的图/色也搬进 `things` 素材区（现在刻意只放第 1 层，避免两处定义）。
