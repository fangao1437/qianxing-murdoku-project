## 五、实现要点与踩坑记录

1. **7×7 通用引擎**（`murdoku_engine_generic.py`）：棋盘尺寸 / 人物字母表 / 房间数可配置；
   分块枚举行列排列避免 25M 峰值；`cellbits` 改为**惰性位集**（7×7 若预生成 n×n² 个
   大位集会占数 GB）；`positions` 走缓存。6×6 关仍用 `murdoku_engine.py`。
2. **7×7 目标摆法必须满足区域规则**：初版 `geom7_base.json` 的 target 使 B 房间人数不占优，
   导致 `t` 根本不在 `rb[B]` 里，前两轮搜索（随机 + 纯 beam）必然无解。修正方式：
   从 `rb[B]` 的 45.8 万合法摆法里挑跨 ≥3 个房间的目标站位。
3. **构造式取代随机撞运气**：严格审计的判据不是「摆法唯一」，而是
   「盗窃者位置唯一 + 假卡覆盖 `b\{t}` 的其余摆法」。据此先贪心把
   `b = rb[h] & 真卡合取` 压到极小，再枚举能覆盖的假卡，命中率从 0 变为可用。
4. **旋转必须同步方位词**：只旋转几何会让「上方/左方」语义错位。本轮把
   上→右 / 下→左 / 左→上 / 右→下、行与列互换一并映射，保证旋转前后题目同构。
5. **门格合法性**：门两端不得落在任何家具格或答案格上；按**移动后**的家具重算，
   否则会出现「门压在新桌子位置」的伪可行解。
6. **数字距离预算按盘面尺寸分档**：7×7 允许 3 条，6×6 允许 2 条。
